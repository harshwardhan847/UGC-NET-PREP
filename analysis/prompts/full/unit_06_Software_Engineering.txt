FORMULAS AND FACTS
- Cyclomatic complexity: V(G) = E - N + 2 = P + 1 = number of regions (P = predicate (decision) nodes; V(G) = number of independent paths)
- Risk exposure: RE = P x L (Probability times loss)
- Cost performance index: CPI = BCWP / ACWP (Earned value over actual cost; schedule index SPI = BCWP/BCWS)
- Availability: A = MTBF / (MTBF + MTTR) (Downtime = (1-A) x period; convert minutes/seconds carefully)
- Exponential reliability: R(t) = e^(-t/MTTF), MTTF = mean of times between failures (Sample: mean 29/5 gives R(1)=e^(-5/29))
- Web app integrity: integrity = 1 - threat x (1 - security) (threat=probability of attack, security=probability of repelling)
- Software maturity index: SMI = (Mt - (Fa + Fc + Fd)) / Mt (Mt=modules in current release; Fa added, Fc changed, Fd deleted)
- Effort from productivity: Effort = size / productivity; size = effort x rate (Check units (person-month vs hour))
- Project duration: days = effort(person-hours) / (team size x hours per day) (1500/(5x8)=37.5)
- Cost from effort: cost = effort (PM) x monthly salary x team; or FP x productivity (Effort in person-months divided by team gives months)
- Basic COCOMO organic: E = 2.4 (KLOC)^1.05 PM; D = 2.5 E^0.38 (Semidetached 3.0/1.12, embedded 3.6/1.20)
- Software (Putnam) equation: E = [LOC x B^0.333 / P]^3 x (1/t^4) (Effort rises as fourth power of compression of time)
- Boundary value analysis count: 4n + 1 test cases for n variables (robust: 6n + 1) (Two variables gives 9)
- Defect removal efficiency: DRE = E / (E + D) (E errors before delivery, D after)
- Cohesion ranking (best to worst): functional > sequential > communicational > procedural > temporal > logical > coincidental (Communicational = same input/output data)
- Coupling ranking (low to high): data < stamp < control < external < common < content (Common = shared global data)
- CMM levels: Initial, Repeatable, Defined, Managed, Optimizing (Repeatable=project management, Defined=process definition, Managed=measurement)
- Maintenance types: corrective (bugs), adaptive (environment), perfective (features/restructure), preventive (Restructuring appears as perfective in nov2020_q20)
- FDD order: overall model, feature list, plan by feature, design by feature, build by feature (Memorise)
- Generic framework activities: Communication, Planning, Modeling, Construction, Deployment (Order D,A,C,B,E in option labels)
- Testing sequence: Unit, Integration, System, Acceptance (Alpha/beta are acceptance)
- Coverage hierarchy: path coverage implies branch implies statement coverage (Reverse not true)
- ISO 9126 characteristics: functionality, reliability, usability, efficiency, maintainability, portability (Reliability not an SRS attribute)

QUESTION FAMILIES (most repeated first; each is a question type the exam keeps reusing)
- Cyclomatic complexity and flow graphs (7x): V(G)=E-N+2=P+1=number of regions; independent paths = V(G).
- Testing type matching (5x): Unit=component, integration=interfaces, system=whole, acceptance=user; regression=no new bugs; white box=condition coverage, black box=ECP/BVA.
- SRS quality attribute definitions (4x): Map definition to attribute: unambiguous=one interpretation, consistent=no conflicts, verifiable=cost-effective check, complete, modifiable, traceable, ranked. Reliability is not an SRS attribute.
- Cohesion types and ranking (4x): Best to worst: functional > sequential > communicational > procedural > temporal > logical > coincidental. Communicational = same input/output data.
- Productivity/effort/time arithmetic (4x): Effort = size/productivity; size = effort*productivity-rate; duration = effort/(team*hours per day).
- Types of maintenance (4x): Corrective=fix bugs, adaptive=new environment/platform, perfective=new features/restructuring for improvement, preventive=future maintainability.
- Reengineering and reverse engineering (4x): Reverse engineering = recover design/spec from code (analysis only, no change); reengineering = reverse + forward restructuring; reasons: adapt, new tech, maintainability.
- CMM maturity levels (4x): 1 Initial, 2 Repeatable (project mgmt), 3 Defined (process definition), 4 Managed (measurement), 5 Optimizing (continuous improvement).
- Configuration management and version control (4x): Commit source and documentation, not generated output; SCM provides versioning, branching, diff; Git is distributed VCS.
- Agile: which models/principles are agile (3x): Agile = XP, Scrum, FDD, ASD, Crystal, DSDM; NOT waterfall/spiral/incremental. Agile principles favour change, customer collaboration, working software, delivering increments; 'following the plan' is the anti-principle.
- Agile/FDD sequence and artifact matching (3x): Memorise FDD order: overall model, feature list, plan by feature, design by feature, build by feature. Agile flow: plan, design, develop, test, release. Scrum=sprint backlog, XP=CRC cards, ASD=speculate-collaborate-learn.
- Cleanroom software engineering (3x): Cleanroom: incremental model, formal specification, statistical (usage-based) testing and certification, correctness verification (static); no unit testing/dynamic verification by developers.
- Elicitation and validation techniques (3x): Elicitation: interviews, questionnaires, ethnography (observation), prototyping, use cases/scenarios, JAD; DFD is analysis, not elicitation. Inspection/reviews/prototype/test-case generation validate requirements.
- UML diagram identity and purpose (3x): Static/structural: class, object, component, deployment, use-case(static view per UGC key). Behavioural: state, activity, sequence, collaboration. Use-case = external actors interacting with system.
- Coupling types (3x): Low to high: data < stamp < control < external < common < content. Common = shared global data; control = one module controls flow of another.
- Software metric categories (3x): Size and complexity = product metrics; LOC/FP normalise by size (size-oriented); indirect measures = functionality, quality, reliability, maintainability.
- Risk management basics (3x): RE=P*L; risk categories project/technical/business; known/predictable/unpredictable; monitoring tracks if risks occur.
- Process model suitability matching (2x): Waterfall=stable requirements; incremental=core product quickly; evolutionary/prototype=unclear reqs; component-based=reuse, compromises inevitable; spiral=risk driven.
- Spiral model characteristics (2x): Spiral = risk-driven, evolutionary/cyclic, suited to changing/unclear requirements, large projects.
- Prototype model phase order (2x): Order: requirements/quick play -> quick design -> build prototype -> customer evaluation -> refine -> deliver/engineer final product.
- Sequence diagram reading (2x): Count lifelines/objects and follow messages top to bottom in time order.
- OO analysis/behaviour modelling step order (2x): OOA order: use-case + activity -> interaction (sequence) -> class -> state chart/object -> component/deployment. Behaviour model: evaluate use-cases, identify events, build state transition diagram, review.
- Software engineering terms matching (coupling/cohesion=design) (2x): Product complexity-> metrics; structured analysis -> requirements; coupling & cohesion -> design; symbolic execution -> validation.
- Design principle definitions matching (2x): Cohesion=intra-module strength, coupling=inter-module dependency, modularity=division, abstraction=hide details, encapsulation=packaging.
- MVC component roles (2x): Model=business logic/domain data, View=UI presentation, Controller=handles input and updates model.
- Availability from MTBF/downtime (2x): Availability = MTBF/(MTBF+MTTR) = uptime fraction; downtime = (1-A)*period.
- COCOMO basics (2x): COCOMO = Constructive Cost Model; basic organic E=2.4(KLOC)^1.05 PM, D=2.5E^0.38; semidetached 3.0/1.12; embedded 3.6/1.20.
- Quality model attributes (ISO 9126) (2x): ISO 9126: functionality, reliability, usability, efficiency, maintainability, portability.
- Quality control vs quality assurance (2x): QC = inspections/tests on products (detective); QA = process, preventive, no code execution.
- Alpha and beta testing (2x): Alpha at developer site, beta at customer site; both acceptance testing.
- Black-box vs white-box technique classification (2x): Black box: ECP, BVA, graph-based; white box: path, loop, data-flow, condition coverage.
- Coverage criteria relations (2x): Path coverage subsumes branch and statement coverage; branch subsumes statement.
- Testing fundamentals statements (2x): Exhaustive testing impractical; testing effort needs early planning and is costly.
- Verification vs validation (2x): Verification = built right (QA, reviews); validation = right product (user needs).
- PERT/CPM and activity charts (2x): CPM repetitive jobs, PERT non-repetitive; critical path = longest path of dependent tasks defining duration; optimistic = shortest time.
