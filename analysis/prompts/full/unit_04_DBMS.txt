FORMULAS AND FACTS
- Attribute closure: X+ = X plus attributes derived by repeatedly applying FDs; X is a superkey iff X+ = all attributes (Attributes never on any RHS must be in every key)
- Candidate key: Minimal superkey; alternate key = candidate not chosen as primary (Candidate key = unique and irreducible)
- Minimal cover: Single-attribute RHS; no extraneous LHS attribute; no redundant FD (Redundant FD = derivable from the rest)
- 2NF: No non-prime attribute depends on a proper subset of a candidate key (Partial dependency means not 2NF)
- 3NF: For each X->A: X is a superkey or A is prime (Transitive dependency on non-prime breaks 3NF)
- BCNF: For each nontrivial X->A: X is a superkey (BCNF => 3NF => 2NF => 1NF; may lose dependency preservation; any 2-attribute relation is in BCNF)
- 4NF / 5NF: 4NF: every nontrivial MVD has a superkey LHS; 5NF: every join dependency is implied by candidate keys (5NF = project-join normal form)
- Lossless binary decomposition: R1 intersect R2 -> R1 or R1 intersect R2 -> R2 (Also check each original FD is preserved in some fragment)
- 3NF guarantee: 3NF synthesis is always lossless and dependency preserving; BCNF is lossless but may not preserve (Classic distractor)
- Cross product and join size: Cross product: degree d1+d2, tuples n1*n2; natural join max tuples n1*n2, min 0 (Outer joins add unmatched tuples (right outer >= |right relation|))
- Relational division: pi(x,y)(R) / pi(y)(S) gives x paired with every y (Use for 'all' queries)
- Degree and cardinality: Degree = number of attributes; cardinality = number of tuples (Snapshot gives both)
- Referential integrity: Insert into referencing and delete from referenced relation can violate; ON DELETE CASCADE deletes referencing tuples (Cascade chains transitively)
- B+ tree leaf order: p*(key + record ptr) + block ptr <= B so p = floor((B - Pb)/(K+Pr)) (B=1024,K=9,Pr=7,Pb=6 gives 63; key for B-tree item was (57,53))
- Conflicting operations: Different transactions, same item, at least one write (Cycle in precedence graph => not conflict serializable)
- Serializability hierarchy: Conflict serializable => view serializable; Thomas write rule only view serializable (Converse false)
- Concurrency protocols: 2PL may deadlock; strict 2PL cascadeless; conservative 2PL and timestamp ordering deadlock-free; tree protocol deadlock-free (Timestamp ordering is conflict serializable)
- Phantom problem: Caused by insertions; prevented by index locking or predicate locking (Not time stamping)
- ACID: Atomicity, Consistency, Isolation, Durability (Deadlock-freedom is not part of ACID)
- Transaction states: Active -> partially committed -> committed; active/partially committed -> failed -> aborted (From active: partially committed or failed)
- Irrecoverable schedule: Tj reads data written by Ti and commits before Ti commits (Cascadeless needs reads only of committed data)
- DDL vs DML: DDL: CREATE, ALTER, DROP; DML: SELECT, INSERT, UPDATE, DELETE (SELECT does not modify data)
- WHERE vs HAVING: WHERE filters rows before grouping; HAVING filters groups after aggregation (Aggregate conditions go in HAVING)
- COUNT variants: COUNT(*) counts rows; COUNT(col) ignores NULL; COUNT(DISTINCT col) counts distinct values (Missing join condition gives Cartesian product (nov2020_q97))
- Top-k correlated query: where (select count(*) from book where price > B.price) < k lists the k most expensive (< 7 gives seven titles)
- varchar vs char: varchar uses actual length; char(n) is padded to n (3 and 20)
- Hadoop roles: NameNode = master, DataNode = worker (Pig-Yahoo, Hive-Facebook, Kafka-LinkedIn)
- Design phases: Requirements, conceptual, logical, physical (Fixed order)
- ER-to-relational: Entity -> table; multivalued attribute -> separate table; M:N -> own table; many-to-one r1 to r2: Pk(r1) -> Pk(r2) (ER-derived relations are at least 1NF)
