FORMULAS AND FACTS
- Attribute closure: X+ = X plus attributes derived by repeatedly applying FDs; X is a superkey iff X+ = all attributes
- Candidate key: Minimal superkey; alternate key = candidate not chosen as primary
- Minimal cover: Single-attribute RHS; no extraneous LHS attribute; no redundant FD
- 2NF: No non-prime attribute depends on a proper subset of a candidate key
- 3NF: For each X->A: X is a superkey or A is prime
- BCNF: For each nontrivial X->A: X is a superkey
- 4NF / 5NF: 4NF: every nontrivial MVD has a superkey LHS; 5NF: every join dependency is implied by candidate keys
- Lossless binary decomposition: R1 intersect R2 -> R1 or R1 intersect R2 -> R2
- 3NF guarantee: 3NF synthesis is always lossless and dependency preserving; BCNF is lossless but may not preserve
- Cross product and join size: Cross product: degree d1+d2, tuples n1*n2; natural join max tuples n1*n2, min 0
- Relational division: pi(x,y)(R) / pi(y)(S) gives x paired with every y
- Degree and cardinality: Degree = number of attributes; cardinality = number of tuples
- Referential integrity: Insert into referencing and delete from referenced relation can violate; ON DELETE CASCADE del…
- B+ tree leaf order: p*(key + record ptr) + block ptr <= B so p = floor((B - Pb)/(K+Pr))
- Conflicting operations: Different transactions, same item, at least one write
- Serializability hierarchy: Conflict serializable => view serializable; Thomas write rule only view serializable
- Concurrency protocols: 2PL may deadlock; strict 2PL cascadeless; conservative 2PL and timestamp ordering deadlock-fre…
- Phantom problem: Caused by insertions; prevented by index locking or predicate locking
- ACID: Atomicity, Consistency, Isolation, Durability
- Transaction states: Active -> partially committed -> committed; active/partially committed -> failed -> aborted
- Irrecoverable schedule: Tj reads data written by Ti and commits before Ti commits
- DDL vs DML: DDL: CREATE, ALTER, DROP; DML: SELECT, INSERT, UPDATE, DELETE
- WHERE vs HAVING: WHERE filters rows before grouping; HAVING filters groups after aggregation
- COUNT variants: COUNT(*) counts rows; COUNT(col) ignores NULL; COUNT(DISTINCT col) counts distinct values
- Top-k correlated query: where (select count(*) from book where price > B.price) < k lists the k most expensive
- varchar vs char: varchar uses actual length; char(n) is padded to n
- Hadoop roles: NameNode = master, DataNode = worker
- Design phases: Requirements, conceptual, logical, physical
- ER-to-relational: Entity -> table; multivalued attribute -> separate table; M:N -> own table; many-to-one r1 to r2: P…
